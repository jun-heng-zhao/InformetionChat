# 设计审查与修改记录

日期：2026-09-18。审查对象为当前 README、docs 下的设计/契约/ADR/治理文档，并只读对照格式转换原型与历史设计。背景：个人开发者、无官方团队或基础服务；重点为插件功能，Agent 与紧急通知采用简单目标。本次止于设计、文档修改与静态检查。

## 1. 审查结论

插件宿主方向成立，主要不足是首版范围混合、跨端隔离缺少验证门槛、接口只有方法清单、简单 Agent/通知被复杂平台能力牵连，以及历史团队业务残留。修订后以一个桌面平台的插件加载、隔离、服务互通和复用为核心，同时验收 Agent 调用服务与授权紧急通知前台弹窗。

文档已形成统一设计基线，仍属于草案。没有生产宿主或正式 SDK，不能把清单验证、示例页面、目标平台和本文修订当成实现通过。完整文档及状态见[开发文档索引](开发文档索引.md)。

## 3. 首版完整验收主线

1. 在已验证的一个桌面平台，断网加载两个 UI 插件；来源、摘要、权限、服务描述和错误原因可查看。
2. 查看器只能传递用户选定的输入；转换器通过自己的服务入口生成结果，宿主保存输出，双方私有存储不可互访。
3. 存在多个提供者时由用户绑定；缺少、停用、升级不兼容、循环依赖和调用超时均有明确结果。
4. Agent 使用独立会话调用相同服务，查询/取消任务并读取结果，不点击插件页面，不自行扩大授权。
5. 用户开启测试插件的紧急来源，前台有效事件直接弹窗；未授权降级，重复不重弹，过期及撤回事件不复活。
6. 停用、取消、权限撤销及更新失败分别验证：旧通道/句柄失效，失控运行时可回收，包与数据恢复一致。

WASM、移动端、联网协议、后台推送、完整备份和通用 Agent 计划接口按后续阶段验收，不应把这些能力默认添加到首版依赖。
