# 桌面插件开发与调试

文档版本：1.0-draft · 2026-09-18。本文定义 Electron 桌面端目标开发体验，借鉴 VS Code 的扩展模型；当前工具尚未实现。

## 1. 目标与边界

插件作者使用一个 manifest、一个服务入口和可选的 Web UI 开发桌面插件。宿主通过声明式贡献点装配命令、视图和设置，通过激活事件延迟启动插件服务，通过独立 Extension Development Host 完成调试。

本项目不兼容 VS Code Extension API、`package.json` contribution schema 或 `.vsix`。现有 `manifest.json`、UI Bridge 和服务契约是唯一兼容边界；借鉴的是进程结构、开发工作流和诊断体验。

开发插件与安装插件具有相同代码执行能力。加载开发目录前必须确认真实路径、工作区和插件信任；Restricted Mode 不启动第三方开发插件。开发模式不会放宽宿主 API 权限、iframe CSP、origin 检查或消息大小限制。

## 2. 插件组成

```text
manifest.json             # 身份、引擎版本、激活事件、贡献点、权限和服务
extension/index.js        # 可选桌面服务入口，在 Node.js Extension Host 中运行
ui/index.html             # 可选 iframe UI 入口
ui/assets/*               # UI 静态资源
schemas/*.json            # 服务输入/输出 schema
README.md / CHANGELOG.md
LICENSE
```

M1 开发工具支持 JavaScript 服务入口；TypeScript 由插件自己的构建步骤编译为 JavaScript。后续受限 WASM 运行时使用独立入口和 SDK，不与 Node.js 权限模型混淆。

manifest 的核心模型：

- `activationEvents`：命令调用、视图首次打开、服务首次调用或工作区显式启动时激活。安装本身不执行插件代码。
- `contributes`：声明命令、视图、菜单和设置。宿主先渲染声明，再在用户触发时激活插件。
- `runtime.ui`：声明沙箱 iframe 入口和 CSP。
- `runtime.extension`：声明纯 JavaScript Node.js Extension Host 入口和引擎范围；运行时复用 Electron 内置 Node，不读取系统 Node。
- `services`：声明提供/消费的版本化服务、schema、效果和 `requiresUI`；可选 `agentCallable: true` 把符合条件的服务列为 Agent 模型工具候选，省略或为 false 时不对 AI 暴露。
- `permissions`：只控制宿主 API；Node.js Extension Host 的系统权限由插件信任决定。

manifest 1.2 草案已经包含 `runtime.extension`；现有 `service/index.js` 只是演示约定，正式包必须迁移到 `extension/index.js`。M1 不支持原生 Node addon、插件自带 Node、Python 或任意外部可执行文件。

## 3. Extension Development Host

开发命令启动一个独立 Electron 窗口和独立数据目录，加载指定开发插件快照。它不复用日常窗口的插件进程、存储、授权或工作区信任，避免测试数据污染正式配置。

启动流程：

1. 解析开发目录并执行与安装包相同的 manifest、路径、schema 和权限校验。
2. 展示目录真实路径、内容摘要、运行时和代码执行风险；用户确认插件信任与测试工作区信任。
3. 创建临时只读快照、独立安装 ID、存储区、iframe origin 和 Extension Host。
4. 按激活事件启动插件；未触发的插件保持未加载。
5. 窗口关闭后终止开发 Extension Host，撤销会话句柄并删除可安全删除的临时状态。

桌面开发入口至少支持选择开发目录、选择测试工作区、启动/停止开发宿主和查看启动诊断。后续 CLI 提供等价的非交互入口；具体命令名在 CLI 实现时冻结。

## 4. 调试与重载

Node.js 服务调试使用 Extension Host 的 Inspector，仅在显式开发模式启用并绑定回环地址。宿主显示实际端口和进程 ID；正式运行不开放调试端口。

开发窗口提供：

- Extension Host 日志：启动、激活、退出、IPC、超时和未捕获异常。
- 每插件 Output 通道：插件可写入有界文本日志；宿主标注插件、安装和会话，不记录资源正文或凭据。
- iframe DevTools：检查 DOM、Console、网络阻断和 CSP；只在开发窗口开放。
- RPC Trace：显示方法、请求 ID、耗时、结果状态和错误码，敏感参数按契约脱敏。
- 运行进程页：查看 Extension Host、iframe、内存、CPU、激活原因和最近心跳。

提供两个明确动作：

- Reload UI：销毁并重建当前 iframe，保留 Extension Host；用于样式和页面脚本修改。
- Restart Extension Host：停止接单、取消任务、终止并重启插件进程，再按激活条件恢复；用于服务代码修改。

首版不承诺任意状态热替换。插件应把需要保留的状态写入宿主管理存储，并处理重复激活与正常停用。

生产运行时在没有可见视图、运行或排队任务、未完成 RPC、获授权后台活动或待处理交互后开始计算闲置时间；连续闲置 5 分钟会关闭 iframe 和 Extension Host。下次激活事件重新创建进程，因此扩展不能依赖进程永久常驻。正在使用的插件不按闲置计时回收。

## 5. SDK 与 API

提供版本化桌面插件 SDK：

- Extension API：注册 manifest 已声明的命令和服务，读取当前上下文，调用宿主资源/任务/通知接口，创建或更新插件视图。
- Web UI Bridge：iframe 使用一次性注入的 API 获取消息端口，发送 JSON-RPC 请求和接收宿主事件；页面不能访问 Electron 或 Node.js。
- 类型与 schema：发布 TypeScript 类型、JSON Schema 和成对请求/响应样例；运行时仍校验所有外部输入。
- 测试工具：提供内存宿主或测试适配器验证激活、服务调用、取消、权限拒绝和通知，不要求启动完整 UI 的测试可在 CI 中运行。

插件模型工具复用服务实现和 schema，不维护另一套 AI 专用业务代码。开发宿主显示最终生成的工具名、说明、输入 schema、效果和不可用原因，并允许用确定性假模型发起工具调用。插件文本只作为工具描述数据，不能注入系统策略或跳过审批。

SDK 只暴露稳定能力。未知方法返回 `-32601`，已知但当前平台不可用的方法返回 `CAPABILITY_UNAVAILABLE`。插件不能导入宿主内部包或依赖 Electron 私有对象。

## 6. 校验、打包与发布

桌面开发工具按同一流水线提供检查、测试、打包和安装验证：

1. 校验 manifest、引擎范围、权限目录、贡献点、路径和服务 schema。
2. 检查 UI CSP、内联脚本、远程资源引用和未声明入口。
3. 运行插件单元测试和可选的 Extension Development Host 集成测试。
4. 生成确定性的 `.plugin.tgz`、文件清单和内容摘要。
5. 在干净临时配置中安装并执行启动/停用冒烟测试。

M1 支持本地文件分发，不建设插件市场。项目不承担默认目录、发布者认证、自动扫描或集中阻止列表的运营责任；以后只有在存在可维护的外部基础设施时才接入相应信任信号。没有该基础设施时，开发工具不得显示“已验证发布者”或“安全插件”等未经证明的状态。

## 7. 验收

- 未触发激活事件时服务进程不启动；首次命令、视图或服务调用只激活目标插件。
- 开发窗口与日常窗口的安装 ID、存储、授权和进程互不共享。
- Restricted Mode、未确认插件或摘要变化时拒绝启动 Extension Host。
- UI 重载和服务重启互不混淆；超时或崩溃后可以查看原因并重新启动，不影响其他插件。
- 日志、Trace 和 DevTools 能定位 manifest、激活、Bridge、CSP、schema、超时和退出问题，默认不泄露正文与凭据。
- 同一包经过校验后产生稳定摘要；打包内容与实际执行快照一致。
