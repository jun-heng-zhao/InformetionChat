# 第三方骨科插件需求附录

本附录整合原《骨科患者手术及随访管理 App 产品需求与技术要求说明书》。业务能力由插件开发者交付和维护，宿主无医疗专属表、命令、量表和导航。本地包不要求项目方签名或认证。本文是后续业务参考，不进入插件宿主 M1 验收。

单人本地版本使用本地工作区和插件私有存储；团队账号、四端共享、服务端校验、角色及远端推送需要业务提供方另行实现服务。下列团队条款仅在该服务存在时适用，不由个人宿主开发者默认承担。缓存加密等医疗交付要求也需业务套件单独实现和验证。

## 1. 目标套件拆分与权限

| 插件 | 职责 | 依赖 |
|---|---|---|
| `publisher.orthopedics-patient` | 患者、就诊、住院号、责任医生 | 本地插件存储；团队成员由可选业务服务提供 |
| `publisher.orthopedics-surgery` | 诊断、术式、侧别、日期、模板 | patient |
| `publisher.orthopedics-records` | 病历、手术记录、术前/术后照片 | patient、surgery、blob |
| `publisher.orthopedics-followup` | 计划、节点、补录、修订、提醒 | surgery、jobs |
| `publisher.orthopedics-scales` | 量表模板、条目、评分和缺失原因 | followup |
| `publisher.orthopedics-export` | XLSX/CSV、研究编号、数据字典 | 前述插件的公开查询命令 |

成员默认可查看同一医疗工作区患者并新增/修改；管理员管理模板、成员、批量导出、恢复和彻底删除。责任医生是资源字段，不自动形成高权限角色；实例可启用按责任医生限制可见性。插件安装不能扩大用户原有权限。

## 2. 数据关系与字段

本地对象通过插件自己的存储接口保存，团队版本按业务服务契约同步，外部业务 ID 不作为平台主键；跨插件通过受保护 ResourceRef 关联。

| 对象 | 字段与规则 |
|---|---|
| Patient | 不可变 ID、工作区、姓名、性别、责任医生、备注、状态；诊断摘要由有效就诊/手术查询生成 |
| Encounter | 患者引用、住院号（字符串、保留前导零）、入院/出院日期、外部机构引用；先确认机构的住院号是患者永久号还是就诊号，模型保存来源命名空间与编号类型 |
| Surgery | 患者/就诊引用、主要及次要诊断、术式、左/右/双侧/不适用、手术日期、责任医生、模板版本 |
| ClinicalRecord | 患者与可选手术引用、类别、术前/术后、检查日期、备注、附件关系、页序；关系需属于同一患者/工作区 |
| FollowupPlan/Node | 手术引用、基准日期、模板快照；节点 ID、偏移规则、计划日、容差、状态 |
| FollowupRecord | 节点引用、实际随访日、NRS、ROM、并发症、备注、原始条目、缺失原因、修订链 |
| ScaleTemplate/Result | 名称、语言、授权、规则版本、原始值、条目分数、总分、缺失规则、计算器版本 |

同一住院号新增时必须提示关联候选患者，不能覆盖现有记录。重复是否允许由管理员策略决定；唯一约束按机构/编号类型设置，不用 `hospitalNumber + 随机 encounterId` 伪造有效唯一约束。患者合并需人工复核、引用迁移清单和撤销记录，禁止仅按姓名合并。

## 3. 目标工作流程与交互（团队服务具备后）

1. 四端登录工作区，查询患者或新建患者/就诊/手术。
2. 患者列表显示姓名、性别、住院号、有效手术的诊断/侧别/术式/日期、下次随访；按更新、手术、随访日期排序。
3. 支持姓名、住院号搜索，诊断、术式、侧别、日期、责任医生、随访状态筛选。
4. 新建分组表单支持草稿、必填提示和离开提醒；正式提交要服务端再次校验。
5. 移动端拍照/选相册、桌面导入/拖放；上传前可删、旋转、排序。保存原图与缩略图，双指缩放，弱网重试，不自动进入公共相册。
6. 首页显示近期、今日和逾期随访；提醒时间窗可配，推送内容不含完整患者身份。
7. 回收站软删除、管理员恢复；彻底删除二次确认并遵守保留/审计策略。

照片类别：门诊病历、手术记录、术前检查、术后检查、管理员自定义其他资料。支持 X 线、CT、MRI 的照片/截图；首版不解析 DICOM、不做 OCR 或诊断。缓存加密，退出清理；截图、分享与录屏按设备和医院策略测试，不能承诺所有系统绝对禁止截图。

## 4. 随访与模板

默认节点：手术日 +14 天、+42 天、+3 个日历月、+6 个日历月、+12 个日历月。日期为工作区日历 date，月底对齐目标月最后一天，闰年处理有固定测试向量；不把手术日转换 UTC 零点后再按设备时区漂移。

容差默认 0 天，管理员可以配置前后窗口。未到期/待随访/逾期由日期和窗口计算，已完成/失访/取消由状态命令产生。医生可临时添加节点。变更手术日期只重算未完成节点；已完成保留原计划、实际日期与修订历史。重试生成计划不会重复节点。

同节点的多次测量与修订分开记录；默认科研导出采用最新有效记录，并输出其版本。NRS 范围 0–10；ROM 记录部位、方向、侧别、单位和测量方法。缺失、未测量、不适用、拒绝回答、失访用不同编码；缺失条目不自动计零。

| 病种模板 | 原需求的量表候选 |
|---|---|
| ACL 重建 | NRS、膝 ROM、IKDC、Lysholm；可选 Tegner/回归运动 |
| 肩关节镜 | NRS、肩 ROM、ASES、Constant |
| 半月板修复 | NRS、膝 ROM、IKDC、Lysholm；负重和恢复状态 |
| 肘关节镜 | NRS、屈伸/旋转 ROM、MEPS |
| 髋关节镜 | NRS、髋 ROM、mHHS 或 iHOT |
| 自定义 | 字段、选项、节点、顺序和量表可配置 |

最终语言版本、授权和计算公式由第三方及临床负责人确认；未获授权的量表在发布包中禁用。管理员可复制、启停模板；历史记录绑定当时版本，不能静默重算。

## 5. 业务导出、治理和验收

科研 XLSX 为第三方导出插件职责。工作表：Patients、Surgeries、FollowUps（每手术节点一行）、ScaleItems、Attachments、DataDictionary；必要时增加 Encounters。英文变量名与中文标签稳定，枚举同时输出编码/说明；数值和单位分列，缺失码单独字段，关联键可追踪。

仅授权角色导出，按诊断、模板、术式、日期、责任医生、完成状态筛选；创建/执行/下载复验权限，保留记录数、筛选条件、模板版本、字典版本、文件标识。研究编号与去标识化为配置；不宣称删除姓名就完成匿名化。

患者授权、代理人、来源、单位、时区、质量标记、外部映射、同步游标和同意撤回均保留扩展接口。患者端、PROM、设备、FHIR、EMR/PACS 属后续第三方连接器。正式医疗文书、伦理、个人信息保护和医院制度由部署方与业务提供方确认。

完整团队套件的后续验收至少覆盖四端共享、团队隔离、重复住院号、不误覆盖、照片分类/缩放/排序、上传中断恢复、五节点日期、改手术日、补录修订、人工评分对照、缺失条目、回收站、越权导出拒绝、XLSX 表关系、退出缓存清理和停用后原始数据交接。
