## 2. 工具链

- Dart 3.13.3 用于当前 `host_core` 和演示器。
- Node.js 用于当前演示插件服务和 Electron 构建。正式 Extension Host 复用 Electron 内置 Node，不再随产品附带第二套 Node；Electron、内置 Node 和包管理器版本在创建桌面工程时锁定。
- Dart 只作为开发工具链存在；正式 Core Host 构建为平台 AOT 可执行文件，用户无需安装 Dart SDK。
- Flutter/WebKitGTK 工具链不再属于已选桌面架构。移动端技术栈尚未决定，不能从本机已安装工具推导。

依赖解析使用 Dart pub workspace，根 `pubspec.yaml` 的 `workspace:` 列出全部包：

```bash
dart pub get                       # 在仓库根执行，一次解析全部成员包
dart analyze                       # 静态检查
```

## 3. 运行演示

```bash
cd /path/to/InformetionChat
dart run tools/demo_runner/bin/demo.dart
```

退出码为 0 表示全部断言通过，非 0 表示存在未通过项。输出分为六步：

1. **加载插件**：清单校验 → 复制为只读快照 → 计算内容摘要 → 用户授权 → 注册服务 → 启动运行时。
2. **绑定提供者**：把 `document.convert` 绑定给查看器和 Agent 会话。
3. **插件互通**：查看器 → `archive.export` → `document.convert` → 结果句柄 → 保存。
4. **Agent 调用**：独立会话发现、描述、使用既有绑定、调用、读取结果，全程不点击插件页面。
5. **紧急通知**：授权来源弹窗、同修订去重、较低修订拒绝、未授权等级降级、未知类别拒绝、缺少有效期拒绝、后台记录 `received`、撤回后禁止重放、插件代确认被拒。
6. **负向用例**：跨会话句柄读取被拒、未声明 `agentCallable` 的服务被拒、未授权调用方被拒、后续阶段接口返回 `CAPABILITY_UNAVAILABLE`、未知方法返回 `-32601`、停用后提供者不可用且句柄撤销、停用一个安装不影响其他安装。

演示产生的暂存快照与输出文件都写在系统临时目录，不污染仓库。

## 4. 演示器覆盖的契约点

| 契约 | 覆盖方式 |
|---|---|
| 身份由通道绑定 | 报文中的 `sourceId`、`pluginId` 一律忽略，改用安装记录生成的值 |
| 权限是交集 | 调用方授权、提供者声明 `agentCallable`、资源接收者三者同时成立才放行 |
| 资源句柄不可伪造 | 句柄由宿主签发，跨会话读取、跨工作区读取、停用后读取分别被拒绝 |
| 输出重新派生给调用方 | 结果句柄归属调用方；下游提供者停用不影响已交付结果 |
| 绑定不被抢占 | `services.bind` 对同一消费方与服务的重复绑定返回既有记录 |
| 统一异步任务 | 所有服务调用返回 `taskId`，结果经 `host.task.get` 读取 |
| 调用链防护 | 成环或超过深度 4 时在任务创建阶段抛 `CALL_CYCLE` |
| 离线代理约束 | 安装记录固定 `offlineOnly`，清单 `connectivity` 为 `network` 时宿主不提供代理网络；演示未验证 Node.js 进程强制断网，也不作此承诺 |
| 通知去重与降级 | 按（工作区, 安装, 来源, `eventId`）去重，等级取用户策略与权限的较小值 |

## 5. 演示阶段的两处替身（必须知道的限制）

这两处是为在无 GUI 环境下验证协议语义而做的替换，**不构成对应能力的实现证据**。

### 5.1 插件服务只有子进程替身，没有 Electron UI

`SubprocessPluginRuntime` 用 `node service/index.js` 承载插件代码，与宿主之间走 newline-delimited JSON-RPC 2.0——帧格式与 `docs/contracts/plugin-ui-jsonrpc.md` 完全一致。

它真实提供：与目标 Extension Host 相同的独立进程形态、真实超时、关闭时强制回收和插件回调宿主的双向通道。

它**不提供**：插件信任、工作区 Restricted Mode、activation events、固定 Node.js runtime、正式 Extension SDK、沙箱 iframe、CSP/请求拦截、独立 origin 或 Bridge 来源验证。这些必须在 M0/M1 分别实现和验证。

正式 Electron 适配器可以复用 `PluginRuntime` 抽象和上层权限、句柄、任务、通知逻辑；manifest 仍需增加 `runtime.extension` 并区分 UI 与服务生命周期。

### 5.2 Agent 只有内部工具调用，没有 API runtime

演示中 Agent 通过 `BridgeDispatcher.bindChannel(kind: 'agent')` 建立会话，验证的是**插件工具授权语义**：独立会话、不可自批、只看到显式 `agentCallable: true` 的服务、缺失绑定返回 `PROVIDER_SELECTION_REQUIRED`。

[Agent API](contracts/agent-api.md) 要求的 `agent-api` profile、持久 runtime 子进程、initialize/session/run/cancel/shutdown、stdout 纯 JSON-RPC、模型适配器、会话事件和 SDK 尚未实现。

## 6. 尚未实现（不要按已完成对待）

- **方法级机器 schema 与成对样例**：实现按契约文字编写，`contracts/examples/` 仍为空。
- **完整 JSON Schema 校验**：当前只检查 `required` 与 `additionalProperties`，未覆盖 `type`、`pattern`、`enum`、嵌套对象，也未由 `plugin-manifest.schema.json` 驱动。清单 schema 与校验代码是两份并行真相来源。
- **正式 Extension manifest**：三个演示 manifest 的服务声明尚缺必需 `description`，仍使用 `service/index.js` 演示约定，未声明正式 `runtime.extension`；因此不能作为完整 schema 合格包。
- **Electron 外壳与插件 UI**：不存在。
- **插件开发宿主**：Extension Development Host、activation events、调试、重载、打包工具和 SDK 不存在。
- **Agent API 模式**：headless profile、模型循环、stdio SDK 与结构化 run 结果不存在；当前只验证了宿主内部工具调用。
- **自动化测试套件**：演示器是当前唯一验收手段，尚未纳入 `dart test`。
- **包格式的压缩包路径**：加载器只处理目录，`.plugin.tgz` 解包与配额尚未实现。
- **数据快照与更新回滚**：`docs/本地数据与备份恢复.md` 的 M1 快照能力未实现。
- **平台支持名单**：只有 Linux 上的无头验证，没有任何实机多端结论。

## 7. 已知实现取舍

| 取舍 | 原因 | 正式化前需要处理 |
|---|---|---|
| 只读快照用逐文件 `chmod 444` 实现 | 兼容性最好 | 逐文件 `chmod` 会为每个文件启动一个进程，包内文件数上限 5000 时不可接受，应改为批量或平台原生方式 |
| 资源内容常驻内存 | 演示输入与结果上限 512 KiB | 超过该规模必须改为受控 blob 存储，不能把正文塞进控制消息 |
| 安装记录、授权、句柄全部在内存 | 演示不与磁盘状态耦合 | 需落盘并在重启后重新校验，授权不得随恢复自动启用 |
| 没有并发限制实现 | 演示为串行调用 | 契约要求每安装并发 4，需要信号量与队列 |
| 演示插件各自复制一份 `host-rpc.js` | 符合"小型工具库随插件打包，不做宿主全局依赖"的规则 | 若插件数量上升，应提供版本化的插件侧 SDK |
