# 插件依赖与能力复用

文档版本：1.3-draft。M1 实现已安装包和服务绑定检查；自动依赖获取、通用事件和聚合搜索后续实现，阶段以 [ADR 0008](adr/0008-solo-developer-delivery-baseline.md)为准。与[本地隔离规范](本地插件隔离与互通.md)配合；方案适用于本地插件及连接不同网络服务的适配插件，不限定中心化或去中心化架构。

## 1. 依赖分层

| 依赖 | 表达位置 | 用途 |
|---|---|---|
| 宿主 API 与运行时 | `engines`、`runtime`、必需/可选能力 | 判断当前设备能否运行 |
| 特定插件包 | `dependencies`：ID、版本范围、是否可选 | 必须使用某插件自身数据模型或专有接口时使用 |
| 一类能力 | `services.consumes`：服务 ID、接口版本范围、是否可选 | 如“转换文档”，由多个插件实现 |
| 私有代码库 | 插件自己的构建依赖与包内资源 | 小型工具库随插件打包，不变成宿主全局插件依赖 |

优先依赖能力契约。例如查看器只要求 `document.convert@^1.0.0`，不强制用户安装某个指定转换器。只有确实依赖特定插件专有行为时，才声明具体包依赖。包版本和服务接口版本独立，转换器升级到 3.x 仍可继续实现接口 1.x。

依赖不自动授予权限。安装 B 以满足 A，不代表 A 能读取 B 的数据，也不代表 B 获得 A 的文件、账号或网络权限。

## 2. 解析、锁定与循环

首版每个工作区同一插件 ID 只有一个活动版本；不同工作区可使用不同版本。磁盘包缓存可按摘要复用，运行实例、存储和授权保持独立。插件 ID 为作者自述命名空间，同 ID 来自不同来源时必须提示冲突，不能自动覆盖。

M1 安装器只在本地候选中检查硬依赖、必需服务绑定、平台和运行时约束，展示受影响插件，再锁定精确版本、内容摘要、来源及提供者绑定。候选不唯一时由用户选择，暂不实现自动求解最优版本组合。离线缺少依赖时返回缺失项，不无限等待。M1 不联网获取依赖，只展示缺失项让用户选择本地包。后续获取依赖使用用户配置的源，不假定维护者运营仓库；目录下载本身不能授权包执行。

如果 A 要求 B 1.x，C 要求 B 2.x，则说明冲突链及可选解决办法：升级兼容消费方、更换能力提供者、停用冲突插件或使用独立工作区。首版不通过悄悄升级 B 或自动加载两份共享状态来掩盖冲突。

必需包依赖与必需服务绑定组成的激活图必须无环，按拓扑顺序激活。可选依赖缺失时允许启动；一旦某可选依赖被纳入激活计划，也不能制造激活环。运行期间的调用环另由调用栈检测，事件互发由限流、来源追踪和消费者幂等限制。

## 3. 功能重复与提供者选择

功能相同的插件可以共存。宿主注册“能力 → 提供者集合”，不按菜单标题猜测功能是否重复，也不让后安装的插件覆盖原命令。

提供者先按接口版本、输入类型、目标格式、当前平台、运行时、联网需求及授权过滤，再按以下顺序选择：

1. 本次调用明确选择且已授权的提供者。
2. 当前工作区对此消费方、服务和输入/输出类型保存的绑定。
3. 用户在兼容候选中选择；可以记为默认。

没有有效绑定时返回 `PROVIDER_SELECTION_REQUIRED`，包含当前可选择的摘要；由应用界面或 Agent 发起选择流程，插件不能自行授予授权。只有一个候选也仍需已有授权或首次确认。默认提供者停用时返回不可用；只有用户事先设置的兼容备选才可切换，记录实际使用者。

界面提供一个“导出/转换”入口，并在其中展示可用提供者，减少重复按钮。不同插件自己的命令 ID 仍保留命名空间。默认绑定不能因更新或新安装而被抢占。

M2 以后搜索可作为另一类聚合：可并行查询多个已授权的来源，按稳定资源 ID 去重并保留来源；不能按正文相似度合并不同会话。发送消息、保存文件等有副作用的操作每次选择一个明确提供者，不向所有提供者广播。

## 4. 功能复用

一个插件可以只提供服务，无需独立页面。例如解析器提供标准文档结构，转换器调用它并生成目标格式，查看器消费最终结果。每步都通过宿主派生资源句柄，并遵守数据范围和联网用途。

一个插件也可以同时提供界面和服务；按钮和 Agent 调用同一个业务操作，避免维护两套逻辑。计算服务尽量与 UI 生命周期分开；需要用户交互的服务显式声明 `requiresUI`。

代码复用与运行时服务复用分别处理：短小纯函数随包构建；需要独立升级、资源消耗较大或被多个插件调用的能力再作为服务。避免为每个辅助函数都增加一个需要用户管理的插件。

服务缓存只在明确数据范围内复用。缓存键至少包含工作区、提供者安装与版本、输入内容/资源版本、参数和授权范围；输出句柄仍按接收者重新授权。不能因为两个用户或插件请求相同，就共享未授权结果。

## 5. 升级与卸载

更新前重新计算依赖图和接口兼容性，展示受影响插件与权限变化；不自动改变默认提供者。输入/输出 schema 的不兼容变化提升服务接口主版本。只扩大插件版本号无法修复接口冲突。

卸载或停用提供者时列出依赖者：必需消费者停止相关激活，可选消费者隐藏相关操作。只清理确定无人引用的安装依赖；用户主动安装或仍被其他插件使用的包不能级联删除。工作区数据默认保留，删除和迁移独立处理。

服务绑定指向安装身份与已锁定契约，来源替换、新权限、数据格式变化都要求重新评估。回滚仅在保留兼容包和数据快照时执行，不能保证所有迁移可逆。

## 6. 接口与验收

M1 宿主提供服务发现、绑定查询、兼容诊断和运行调用；选择提供者与安装操作由宿主界面完成。Agent 使用已有绑定并在缺失时报告原因。依赖变更计划、Agent 安装管理及自动备选切换后续按需开放。

- 必需依赖缺失、两个范围冲突、来源冲突和循环依赖给出可定位的依赖链。
- 两个转换器可共存，默认绑定稳定，卸载默认提供者不会偷偷交给另一个插件。
- 同一能力可由不同语言/运行时实现；消费方不需要访问其内部数据结构。
- 可选服务缺失只降级相应入口，主要功能可继续使用。
- 首次调用与 Agent 调用共用相同选择、资源传递及权限检查。
- 对有副作用的能力不做自动广播、隐式重试或无提示备选切换。
