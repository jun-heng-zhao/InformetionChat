# 本地数据与备份恢复

状态：配套设计，2026-09-18；尚无存储实现。M1 使用资源保存和更新前快照规则，完整归档导入/搜索及工作区备份恢复在 M2 完善，不能替代插件主线。结构定义见[数据字典](data/data-dictionary.md)，归档字段见 [chat-export.v1](contracts/chat-export.schema.json)。

## 1. 数据归属和保存

宿主保存标准归档、会话、消息、附件元数据和导入记录；插件保存自身配置与业务对象。停用或卸载插件保留宿主已导入的标准记录。插件私有数据由其版本化导出接口解释；宿主保留原始字节不代表能够显示任意行业对象。

本地数据方案使用 SQLite 保存结构化数据，附件内容存入工作区专属目录，以摘要去重。文件先写暂存区并校验，再提交数据库引用；中断产生的无引用文件可清理。全文索引可重建，原始记录不能依赖索引恢复。每个 profile 只有一个 Dart Core Host，它是工作区唯一写入宿主并串行化事务；第二窗口和 Agent client 连接现有 Electron Supervisor，第二 Core Host 不得直接打开数据库。具体锁与恢复见 [Desktop Core IPC](contracts/desktop-core-ipc.md)。

工作区隔离针对经宿主访问的插件；同一操作系统账号、设备管理员或设备恶意软件可能直接读取应用文件。初期使用系统目录权限，凭据如以后引入则使用系统安全存储；暂未设计数据库及备份口令加密，界面和发行说明不得标为“已加密”。日志不记录消息正文、文件内容或令牌，保留最近 7 天且总量不超过 20 MiB。

## 2. 标准归档导入

1. 宿主经选择器取得文件，校验 UTF-8、JSON 结构、schema 版本及限额。日期启用实际格式校验；未知主版本拒绝导入并保留原文件。
2. 除 JSON Schema 外执行语义校验：各对象 ID 非空且在各自集合中唯一；消息引用的会话和附件必须存在。含消息的包必须包含对应 `channels`；空包可省略会话。`authorId` 是来源内标识，缺少作者资料时以该标识展示。
3. `workspaceId` 仅为来源元数据，目标工作区由宿主当前界面确定。导入内容、`visibility`、作者 ID 均不能建立本地权限或恢复外部账号。
4. 在目标工作区生成 `importId`，按 `importId + objectType + sourceId` 建立本地 ID 映射。两个包使用相同消息 ID 时仍保持独立；当前归档方案不自动合并增量归档或推断账号对应关系。
5. 同一目标工作区已导入相同原文件 SHA-256 时，返回原导入结果并提示跳过。内容不同的包作为新的独立导入，用户可预览记录数和来源后确认。重复 JSON 键、非法关联和超过限额的输入整包拒绝，不悄悄丢弃字段或记录。
6. 在暂存区构建全部记录，单次事务发布。取消、磁盘不足或校验失败保持已有数据不变；重启清理未提交的暂存区。全文索引完成前显示覆盖状态，搜索结果不得冒充完整数据。

正文按纯文本展示；文件名作为标签处理。链接仅在用户操作后交给受控外部打开流程；导入不会执行 HTML、脚本或自动下载附件。

归档模块初始上限为单个 JSON 20 MiB、10,000 条消息、单条正文 256 KiB、10,000 条附件元数据、嵌套深度 32。这是宿主归档模块的预算，M1 插件资源仍使用 Bridge 的较小限额。限额需在基准机器验证后写入发行说明；超过限额给出具体原因。

## 3. 标准导出与附件

标准 JSON 导出使用一致性读取快照，保存当前授权范围内的消息及所需会话、附件元数据。导出前重新映射 ID 和引用，避免来自不同导入包的原 ID 冲突；保留来源对应关系在本地导入记录中。`snapshotAt` 表示本次导出的读取时间，消息时间保留原有时区信息。

`chat-export.v1` 仅携带附件元数据，不携带附件文件、作者展示名、完整修订历史、连接配置或插件私有数据。界面标注“记录导出（附件清单）”。离线导入后缺少附件正文时显示“未包含文件”，不根据文件名或摘要自动联网查找。完整数据迁移使用工作区备份。

保存先写临时文件，成功后替换目标；覆盖已有文件由用户确认。目标文件系统不支持原子替换时保留原文件，另存新文件并说明结果。取消不能留下被误认为成功的最终文件。

## 4. 工作区备份与恢复

备份是独立的宿主管理操作。M2 提供用户主动创建和恢复本地备份；版本迁移前创建恢复点。用户自行保存设备外副本，同盘快照只用于迁移回退。

备份包包含版本化 `backup.json`、SQLite 一致性快照、附件文件及插件存储快照。`backup.json` 记录格式版本、宿主版本、数据库版本、各插件数据版本和 offlineOnly 约束，以及每个条目的路径、字节数和 SHA-256。插件可执行包仅记录来源、版本及摘要，恢复后由用户重新安装；所有插件默认停用。备份不包含凭据、短期句柄、运行中任务、授权会话或可直接复用的权限批准。宿主暂停工作区写入并停止插件后生成快照，不能直接复制正在写入的数据库文件。

恢复先校验版本、路径、条目数、大小和摘要，再在新的工作区目录中试恢复。禁止路径穿越、链接条目和未列入清单的文件；所需空间包括解包与校验暂存，空间不足在写入前拒绝。数据库校验通过后登记新工作区，原工作区保留供用户核对。插件存储仍为未授权数据，安装与数据版本匹配后由用户决定是否启用。

迁移失败恢复数据库和相关插件数据的同一快照；仅回退程序版本不能保证恢复。更高版本的数据不可由旧客户端直接写入；保留只读诊断及恢复入口。永久删除工作区会说明对备份副本的影响，宿主不能自动擦除用户另存的副本。

## 5. 验收

- 导入后导出再导入，消息正文、时间、撤回标记和附件关联一致；ID 可重新映射，来源映射可追踪。
- 相同文件重复导入不重复记录；同 ID 的不同包不相互覆盖；非法会话和附件引用整包拒绝。
- 取消、磁盘不足和提交前异常退出后，原数据仍可查询；索引可重建。
- 在空目录恢复备份，记录数、附件摘要和插件存储一致，旧权限及会话均不复活。
- 迁移失败可恢复同一份完整快照；破损、新版本或越界备份不能覆盖当前工作区。

备份清单的机器 schema、样例包及上述自动化用例随 M2 实现交付；完成恢复演练前不能宣称支持可靠备份。
