# 本地插件隔离基线 v1.2 草案

设计要求，由未来客户端执行，不依赖审核服务；M1 以离线 UI 插件为范围。详见[隔离与互通规范](../本地插件隔离与互通.md)。

- 插件代码不直接进入宿主主执行环境；UI 独立源/存储，Worker 受限导入与资源预算。
- 不提供任意数据库、目录、环境变量、网络、系统 shell 或进程启动权限。
- 文件、聊天、网络与跨插件数据传递均由宿主逐次授权。
- 插件存储按工作区和安装隔离；同名插件的不同安装不共享上下文。
- 插件之间只通过命令/服务、事件与短期资源句柄互通；权限不得在调用链中放大。
- 离线输入不能通过提供者其他任务或持久状态外发；离线安装不能在更新、恢复或重新授权后原地获得网络权限，需空存储的新安装和新的数据分享授权。
- 超时、取消、循环调用和事件洪泛有明确限额；停用撤销任务、订阅、通道与句柄。
- 本地未签名包仅在已验证的运行时授权加载；来源信息和内容摘要用于识别，不是安全认证。开发目录先生成只读安装快照，避免校验与执行内容不同。
- 更新后重新检查接口和权限；删除插件数据单独确认，回滚不能忽略数据格式兼容。
- 桌面和移动隔离分别验证，WebView 独立进程本身不能证明安全沙箱成立。
