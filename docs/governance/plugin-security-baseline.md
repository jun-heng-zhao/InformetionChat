# 桌面插件信任与隔离基线 v1.3 草案

设计要求，由未来 Electron 客户端执行；M1 以本地可信插件为范围。详见[隔离与互通规范](../本地插件隔离与互通.md)和 [ADR 0009](../adr/0009-electron-desktop-plugin-runtime.md)。

- 插件代码不进入 Electron 主进程、工作台 renderer 或 Dart Core Host；UI 使用禁用 Node.js、按安装和包摘要派生独立 origin 的沙箱 iframe，服务使用复用 Electron 内置 Node 的独立 Extension Host `utilityProcess`。
- Extension Host 采用 VS Code 式信任模型。用户启用插件即允许其以当前账号权限读写文件、联网和启动进程；独立进程只提供稳定性边界，不宣称隔离恶意代码。
- 文件、聊天、代理网络与跨插件数据传递通过宿主 API 时逐次授权；权限矩阵不能限制插件直接使用 Node.js 或系统 API。
- 插件存储按工作区和安装隔离；同名插件的不同安装不共享上下文。
- 插件之间只通过命令/服务、事件与短期资源句柄互通；权限不得在调用链中放大。
- `connectivity: offline` 阻断 iframe 和宿主网络代理，不构成 Extension Host 的强制断网保证；需要运行不可信代码时使用后续 WASM 或 OS 沙箱运行时。
- 超时、取消、循环调用和事件洪泛有明确限额；停用撤销任务、订阅、通道与句柄。
- 本地未签名包启用前显示真实来源、内容摘要、代码执行风险和权限；插件信任与工作区信任分别记录。来源信息和摘要用于识别，不是安全认证。开发目录先生成只读安装快照，避免校验与执行内容不同。
- Restricted Mode 不启动第三方 Extension Host，也不允许工作区内容触发插件代码。摘要、入口或来源变化后撤销原插件信任。
- 安装界面明确区分 Web 沙箱 UI、受信任 Node.js 本地代码和后续 WASM 受限计算；Node.js 包必须提示其可按当前用户权限访问系统，不能用较短的宿主权限列表暗示安全沙箱。
- 正在使用的插件不按 5 分钟定时策略回收；符合闲置条件连续 5 分钟后关闭 iframe 和 Extension Host。桌面进程组超过 5 GiB 总常驻内存时显示诊断并建议用户审查，不自动终止使用中的插件。
- 更新后重新检查接口和权限；删除插件数据单独确认，回滚不能忽略数据格式兼容。
- iframe 同时验证 CSP、请求拦截、origin、顶层 frame 和消息端口；只依赖其中一项不能证明 UI 边界成立。
- Android、iOS 均不加载第三方插件、开发目录或 Extension Host，只运行随应用构建的内部模块；开发顺序为 Android、iOS。
