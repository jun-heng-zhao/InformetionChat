# ADR 0008：个人开发者的分阶段交付基线

状态：当前设计基线，2026-09-18；实现与平台验证待完成。本文已合并仍有效的宿主原则，旧决策文件已清理；编号保留。

## 背景

项目由个人开发者维护，没有官方团队、统一账号、后台、认证机构或默认插件仓库。现有设计已移除发布审批，但仍混合四端、复杂运行时及服务方案，缺少可独立完成的首版。用户明确重点是插件功能，Agent 与紧急通知采用简单目标。

## 决策

1. 首版围绕插件加载、隔离、互通和能力复用交付；以两个离线插件转换选定资源为主线。Agent 调用同一服务，紧急通知验证授权来源的前台弹窗，两者都进入 M1 验收。
2. 四端保留为目标。先在一个桌面平台完成运行时验证和可用版本，再逐端扩展；暂以 Linux 为验证环境，若 WebView 阻断，可改用 Windows 完成首个平台。实际支持名单以版本测试记录为准。
3. 按 M0 可行性验证、M1 单桌面插件首版、M2 开发与数据完善、M3 单项扩展交付。M1 提供本地安装、手动更新、已安装依赖检查、服务绑定、简单 Agent 适配和前台紧急通知；自动依赖下载、通用事件、Worker、远程 Agent、后台推送和网络目录后续实现。
4. WebView 先验证资源拦截、独立存储、桥接身份和退出回收。无法建立边界的平台关闭外部插件入口，继续交付本地基础功能；重新选择运行时后再开放。声明未签名可加载不等于所有平台均可安全加载。
5. M1 离线插件安装记录永久保持无网络出口。未来开放网络时，读取过离线输入的安装不能原地获得网络权限；使用空存储的新安装并由用户选择要重新分享的数据，避免缓存后外发。
6. M1 保证选定资源和转换结果可保存，更新前保存可恢复的数据快照。完整工作区备份与搜索在 M2 完善；短期句柄、账号凭据、插件授权和运行会话不通过恢复自动启用。
7. 项目维护宿主、公开契约和随包模块；插件作者维护插件，服务提供方维护远端服务。没有默认审核、官方认证、集中撤回、推送中继或全天值守的交付义务。
8. 草案版本号和 schema 校验不构成 SDK 可用证明。每阶段只公布经过实现与测试的能力，未实现的方法明确返回不可用。开源许可证、平台依赖许可证和构建条件在首次分发前确认，不从示例插件的 MIT 字段推定整个项目许可。

## 宿主原则

- 宿主负责通用工作区、权限、插件生命周期和基础数据；格式转换、骨科及平台协议由插件提供，业务字段留在插件模型中。
- 本地包允许未签名，所有插件采用相同公开接口和授权规则。作者、来源、签名或随包身份均不增加权限；结构校验和运行隔离由客户端执行。
- 插件代码通过独立 WebView 或后续受限 Worker 运行。服务、资源和事件由宿主代理，不能直接共享私有数据库、内存、路径或凭据；调用链的权限只保持或收窄。
- 包依赖、能力依赖和构建依赖分别表达；用户绑定服务提供者，精确版本与来源由安装记录锁定。首版不直接运行其他生态的 Node/Python/原生插件。
- 四端沿用 Flutter/Dart 候选架构和统一接口语义，原生能力随客户端构建；服务拓扑由连接器适配，远端运营由接入方承担。

## 后果

插件互通、Agent 调用和前台紧急通知成为同一首版流程；通用平台能力按需求扩展。WASM、移动适配、网络和后台通知设计继续保存，按阶段启用。主文档、客户端矩阵和各附件同步标注范围，旧业务需求仅作为后续参考。
