# ADR 0008：个人开发者的分阶段交付基线

状态：当前设计基线，2026-09-18；实现与平台验证待完成。本文已合并仍有效的宿主原则，旧决策文件已清理；编号保留。

## 背景

项目由个人开发者维护，没有官方团队、统一账号、后台、认证机构或默认插件仓库。现有设计已移除发布审批，但仍混合四端、复杂运行时及服务方案，缺少可独立完成的首版。用户明确重点是插件功能，Agent 与紧急通知采用简单目标。

## 决策

1. 首版围绕插件加载、隔离、互通和能力复用交付；以两个离线插件转换选定资源为主线。Agent 调用同一服务，紧急通知验证授权来源的前台弹窗，两者都进入 M1 验收。
2. 桌面端是主要产品，先按 [ADR 0009](0009-electron-desktop-plugin-runtime.md) 在 Linux 完成 Electron 验证和可用版本，再适配 Windows；随后依次开发 Android、iOS 轻量信息收发器。不规划 macOS。移动端不提供第三方插件、市场或开发加载。实际支持名单以版本测试记录为准。
3. 按 M0 可行性验证、M1 单桌面插件首版、M2 桌面开发与数据完善、M3 桌面扩展及移动轻量客户端交付。M1 提供本地安装、手动更新、已安装依赖检查、服务绑定、简单 Agent 适配和前台紧急通知；自动依赖下载、通用事件、Worker、远程 Agent、后台推送和移动信息收发后续实现。
4. Electron iframe 先验证资源拦截、独立 origin、桥接身份和退出回收；插件服务进程采用显式信任模型。无法建立 iframe、Restricted Mode 或信任门槛的平台关闭第三方插件入口，继续交付本地基础功能。
5. M1 的 `offline` 约束宿主代理和插件 UI 网络加载，不构成对已信任 Node.js 插件服务进程的 OS 级断网保证。涉及敏感数据时，用户必须理解插件代码具有当前账号权限；需要强制隔离的场景后续使用 WASM 或 OS 沙箱运行时。
6. M1 保证选定资源和转换结果可保存，更新前保存可恢复的数据快照。完整工作区备份与搜索在 M2 完善；短期句柄、账号凭据、插件授权和运行会话不通过恢复自动启用。
7. 项目维护宿主、公开契约和随包模块；插件作者维护插件，服务提供方维护远端服务。个人维护者不运营默认插件源、审核、官方认证、签名、扫描、集中阻止列表、推送中继或全天值守服务。用户负责判断本地插件来源，宿主负责准确展示路径、摘要和代码执行风险。
8. 草案版本号和 schema 校验不构成 SDK 可用证明。每阶段只公布经过实现与测试的能力，未实现的方法明确返回不可用。开源许可证、平台依赖许可证和构建条件在首次分发前确认，不从示例插件的 MIT 字段推定整个项目许可。

## 宿主原则

- 宿主负责通用工作区、权限、插件生命周期和基础数据；格式转换、骨科及平台协议由插件提供，业务字段留在插件模型中。
- 本地包允许未签名，但启用前必须确认来源、摘要和代码执行风险。未签名包的作者字段不可验证；工作区信任与插件信任分别记录。所有插件通过宿主 API 时采用相同授权规则。
- 插件 UI 通过 Electron 沙箱 iframe 运行，插件服务通过独立 Extension Host 进程运行。服务、资源和事件经宿主代理时不能直接共享私有对象或凭据；已信任服务进程仍具有当前用户的系统权限。
- 包依赖、能力依赖和构建依赖分别表达；用户绑定服务提供者，精确版本与来源由安装记录锁定。首版不直接运行其他生态的 Node/Python/原生插件。
- 桌面采用 Electron Supervisor 并保留 Dart AOT Core Host；Extension Host 复用 Electron 内置 Node，不要求用户另装 Node 或 Dart。Android 只复用数据与服务接口，少量内部模块随应用构建，不执行用户安装的插件代码。服务拓扑由连接器适配，远端运营由接入方承担。

## 后果

插件互通、Agent 调用和前台紧急通知成为同一首版流程；通用平台能力按需求扩展。WASM、移动适配、网络和后台通知设计继续保存，按阶段启用。主文档、客户端矩阵和各附件同步标注范围，旧业务需求仅作为后续参考。
