# 本地插件隔离与互通

文档版本：1.4-draft。范围以 [ADR 0008](adr/0008-solo-developer-delivery-baseline.md)和 [ADR 0009](adr/0009-electron-desktop-plugin-runtime.md)为准。M1 优先实现 iframe UI 边界、插件信任、服务互通及复用；通用事件和受限计算运行时后续验证。本文是设计要求，尚无生产 Electron 运行时实现。

## 0. 威胁边界和开放条件

桌面插件采用 VS Code 式信任模型。iframe 隔离防止页面直接进入宿主 UI、Node.js 和任意本地资源；宿主 API 权限防止正常插件误用未授权数据。用户确认并启用的插件服务进程属于受信本地代码，拥有当前用户授予应用的系统权限，可以绕过宿主 API 读写文件、联网或启动进程。本设计不声称约束恶意的已信任插件。

来源摘要用于识别内容是否变化，不能证明作者身份或安全性。未签名包的 `publisher` 是自述字段；项目不运营默认插件源、签名、扫描或阻止列表，用户需按实际来源和摘要决定是否信任。工作区信任只控制工作区内容能否触发插件执行，不替代插件信任。

安装界面将运行等级明确显示为“Web 沙箱 UI”“受信任 Node.js 本地代码”或后续“WASM 受限计算”。包含 `runtime.extension` 的包必须显示“可按当前用户权限读取文件、联网和启动进程”，用户确认后才能执行。宿主 API 权限列表用于控制正常调用和数据流，不能以权限较少暗示 Node.js 代码受到系统级限制。

M0 在固定 Electron 版本上验证：iframe 导航/重定向、图片/字体/媒体子资源、fetch/XHR、WebSocket、WebRTC、Worker/Service Worker、弹窗/下载、外部协议和 `file:`，以及伪造 Bridge 消息和跨安装存储。CSP 为宿主不可放宽的下限，插件自带 CSP 只能进一步收紧；请求拦截和独立 origin 同时生效。

验证须覆盖实际 Linux 系统及 Electron/Chromium/Node.js 版本，并验证卡死时能回收 iframe 和服务进程。iframe 来源校验、Restricted Mode 或信任门槛失效时关闭第三方插件加载，保留宿主基础功能。信任确认是服务进程执行系统操作的授权边界，不能包装成 OS 沙箱；插件授权也无法控制插件进程或外部 Agent 已合法读取的数据。

## 1. 隔离单位

宿主为每个工作区内的插件安装分配 `installationId`，每次激活生成新的会话。插件 ID 用于名称和依赖解析；安装 ID 与会话用于权限判断。同一个包在两个工作区运行时不能共享存储、事件或文件句柄。M1 先串行处理同一安装的有副作用调用，取消失败时关闭该运行时并使相关任务失败，不能只停止等待而让代码继续工作。

| 边界 | 宿主执行方式 |
|---|---|
| UI | 每安装和包摘要派生 `ichat-plugin://<originKey>` 与独立消息端口；禁用 Node.js，关闭任意导航、远端子资源、弹窗及直接文件访问；CSP 配合请求拦截 |
| 插件服务 | 每安装独立 Electron Node `utilityProcess`，隔离崩溃、卡死和生命周期；按用户信任获得当前账号权限，不作为恶意代码沙箱 |
| 工作区 | `restricted` 状态不启动第三方服务进程，也不允许工作区内容触发插件代码；插件信任与工作区信任分别记录 |
| 受限计算 | 后续 WASM Worker 不默认提供 WASI 文件目录、环境变量或 socket；只导入允许的宿主能力 |
| 存储 | 由宿主按工作区/安装命名空间操作；不传数据库连接、目录路径或其他插件的存储键 |
| 文件 | 系统选择器创建不可伪造的短期句柄，绑定接收者、读写范围和会话 |
| 网络 | iframe 和宿主代理按策略阻断或代发；受信 Node.js 插件进程可直接联网，除非未来选择额外 OS 沙箱运行时 |
| 凭据 | 系统安全存储保存，插件只能请求针对指定目标的代发，不取得明文令牌 |
| 执行资源 | 限制 IPC 消息、并发、时间、日志量；WASM 另有内存和执行预算；UI 采用各端可验证的限制 |

Electron Extension Host 进程主要提供稳定性和生命周期隔离。若业务需要运行不可信代码，必须另选 WASM 或 OS 沙箱运行时并单独验收，不能沿用普通 Node.js 进程的安全声明。插件崩溃的验收目标是宿主数据完整、其他插件可继续操作。移动端不运行第三方插件。

Extension Host 数量不设固定上限，桌面进程组总常驻内存超过 5 GiB 时提示用户审查。正在使用的安装不按 5 分钟定时策略回收；无视图、任务、RPC、获授权后台活动或待处理交互并连续闲置 5 分钟后关闭运行时，下次按激活事件重新创建。接近阈值时停止后台预热并回收符合条件的闲置安装；越过阈值不自动终止使用中的插件，具体规则见 [Desktop Core IPC](contracts/desktop-core-ipc.md)。

宿主 API 权限由本地用户授予，默认关闭文件、网络、聊天和跨插件数据访问。未签名、随包、项目维护者编写的插件调用宿主 API 时使用同一规则。权限变更即时作用于新调用，撤销时取消仍在运行的相关任务；它不能撤销服务进程已经通过系统接口取得的数据。

## 2. 互通接口

宿主注册表分开处理供用户触发的命令和供插件调用的服务。下列服务接口在 M1 实现，通用事件接口在 M2 实现。服务按操作粒度命名，例如 `document.convert`；服务 ID、接口版本与插件自身版本彼此独立。提供者随包附带输入和输出 JSON Schema，消费方声明所需接口版本范围。

| 接口 | 目的 |
|---|---|
| `host.service.discover` | 查找当前工作区可授权的兼容服务；返回摘要，不暴露私有对象 |
| `host.service.call` | M1 调用已绑定服务并返回 taskId，通过 task.get 取得结构化结果 |
| `host.event.subscribe` | 订阅清单声明的主题，接收经授权的事件 |
| `host.event.publish` | 发布插件命名空间内的事件，禁止冒充宿主事件 |
| `host.task.cancel` | 取消当前调用链中有权管理的任务 |

提供服务不等于允许所有插件调用它。用户授权“消费插件 → 服务 → 提供插件”的连接，宿主保存绑定和数据传递范围。发现新实现不能覆盖已有绑定。不存在兼容提供者时，必需服务阻止依赖激活，可选服务只禁用相关操作。

插件不得通过宿主 API 直接引用另一插件的代码、私有数据库、iframe DOM 或内部对象。可以共享的数据来自已声明接口，数据格式通过版本演进，不要求两端使用同一种语言。受信插件进程若直接扫描用户文件，属于插件信任风险，宿主接口权限无法拦截。

## 3. 一次调用的流程

以“查看器把选定聊天归档交给转换器”为例：

1. 查看器声明消费 `document.convert`，转换器声明提供该服务和输入/输出 schema。
2. 用户选择提供者、输入归档和目标格式。宿主生成仅限该归档的只读引用，并确认允许向此提供者传递。
3. 查看器调用 `host.service.call`，仅传服务 ID、版本范围、请求参数和资源引用；接收者由已保存绑定确定。
4. 宿主验证双方状态、声明、授权、工作区、版本、参数及资源范围，创建绑定调用链的上下文。
5. 宿主为转换器派生仅本次调用有效的只读句柄。转换器在自己的运行时生成输出，不获得查看器存储或全部聊天访问权。
6. 宿主校验输出结构和大小，生成返回给查看器的结果句柄。用户经系统保存器选择输出位置。
7. 结束时撤销提供者的临时输入句柄；结果句柄绑定调用方会话或任务，在声明的有效期内可读取并继续授权传递。取消、超时、停用或权限撤销按对应范围释放临时资源，不能刚返回结果就使其无法读取。

```json
{
  "jsonrpc": "2.0",
  "id": 12,
  "method": "host.service.call",
  "params": {
    "service": "document.convert",
    "versionRange": "^1.0.0",
    "input": {"source": "resource:opaque-handle", "targetFormat": "markdown"}
  }
}
```

示例句柄仅表示形状，不是可复用的真实授权。schema 本身不能识别资源权限；宿主从句柄表校验接收者、版本、权限及有效期，不能相信 JSON 字段中的文件路径或用户 ID。

## 4. 防止通过其他插件扩大权限

每次跨插件调用分别校验：调用者是否有权发起操作、是否有权分享输入、提供者是否有权执行所声明操作。数据范围只能保持或缩小。提供者不自动继承调用者的所有权限，调用者也不能借提供者权限访问更大数据集。

由宿主按受信通道注入调用上下文，不接收插件自报的来源。跨插件服务默认只获得显式传入的资源；读取提供者自身业务数据、联网或写入持久状态，必须在服务绑定的授权中列明。把导出句柄交给有网络权限的插件时，需要用户允许该数据用途和目标。

首版对服务提供者采用保守约束：同一安装使用一致的允许范围。不能在同一 UI 上下文里一边处理“仅本地”的敏感输入，一边继续运行已授权联网的后台逻辑。若两个调用要求不同权限，宿主应拒绝组合或使用没有共享可写内存/存储的独立执行上下文。只有上下文 token、没有运行状态隔离，不能防止插件缓存后再外发。

M1 的 `offline` 是宿主代理和 iframe 的持续约束，包含所有必需/可选依赖和实际调用链。宿主不会为离线安装代发网络请求，iframe 不能加载远程资源。普通 Node.js Extension Host 仍可使用系统网络，因此该声明是可信插件契约，不是恶意代码隔离保证；需要强制断网时只能使用后续受限运行时。

停用或撤销句柄不能抹去插件已经读取并缓存的内容。暂不实现完整信息流追踪；无法保证无共享状态时拒绝把离线资源传给联网安装。通知仅允许向获授权的用户展示摘要，其他插件读取通知正文仍需数据授权。

命令调用、事件和任务结果同样执行数据流授权，不能成为服务调用的旁路。跨插件服务不自动重试写操作；可重试任务使用幂等键，失败结果需说明是否已经产生副作用。

## 5. 生命周期和失败处理

初始预算建议：消息 1 MiB、普通调用 30 秒、每安装并发 4、调用链深度 4；这些是待验证配置，不是已测性能。宿主维护 trace 和活动服务栈，拒绝循环调用；父调用取消向子调用传播。大文件通过限额句柄读取，长计算分批执行或创建可取消任务。

通用事件在 M2 首次实现时采用有界内存队列，按订阅者隔离。M1 的任务状态与通知直接经宿主接口查询，不依赖通用事件总线。队列溢出或重连时报告丢失，由消费者查询当前状态；不承诺持久可靠投递。状态变更携带资源版本，事件默认只有引用；通过事件传递正文同样需要显式授权。

停用顺序：停止接单 → 撤销订阅和共享授权 → 取消任务 → 关闭 iframe/消息端口/Extension Host → 保留数据。旧会话恢复不了旧授权。更新后重新检查摘要、信任、服务兼容性和权限；提供者停用返回 `PROVIDER_UNAVAILABLE`，不自动选用未知提供者。

错误码包括 `CAPABILITY_DENIED`、`CAPABILITY_UNAVAILABLE`、`PROVIDER_UNAVAILABLE`、`CONTRACT_MISMATCH`、`RESOURCE_EXPIRED`、`TIMEOUT`、`CANCELLED`、`CALL_CYCLE`。错误带请求 ID，不包含其他插件的私有数据。

## 6. 兼容尚未出现的插件

通过稳定协议扩展插件种类，按需增加小接口：文件/记录查看、转换、搜索、消息连接器、计算任务。宿主只掌握记录、附件、任务和服务等公共概念，不增加具体格式或行业分支。

清单区分运行时、客户端平台、必需能力、可选能力、依赖和服务契约。缺失必需能力时说明具体原因；缺失可选能力时允许基础部分运行。桌面包声明的运行时必须全部可用。移动端不安装桌面插件，只构建产品选择的内部模块。

与已有生态的兼容通过适配器完成：它将现有协议映射为版本化服务，数据 schema 转换也由适配器承担。M1 只提供固定 Node.js Extension Host 运行时；原生 ABI、Python、任意可执行文件及长期后台驻留不默认开放。

M1 用查看器与转换器验证数据传递，并验证 Agent 调用同一服务及插件提交前台通知。M2 起补充通用事件与开发工具，随后按需求验证其他计算实现和联网连接器。暂不开发通用工作流编辑器、跨插件共享数据库或任意脚本执行系统。

## 7. 验收场景

- 同一包的两份安装不能访问彼此的存储和句柄；伪造工作区或安装 ID 无效。
- 用户只选择一份文件时，提供者不能读取同目录其他文件、其他聊天或调用方存储。
- 用户同意一次传递后服务可返回结果；取消、停用后再次使用句柄被拒绝。
- 消费方与提供者接口不兼容、依赖循环、运行时缺失时能准确诊断，不影响无关插件。
- 宿主 API 不会把本地输入交给未授权服务或网络代理；已信任 Node.js 插件仍可通过系统接口自行读取或外发数据，此风险必须在启用前展示。
- M1 验证超时和 UI 卡死回收；M2/M3 增加事件洪泛与 Worker 自旋限制，宿主及其他插件仍可操作。
- M3 Android 与 M4 iOS 信息收发器均不提供第三方插件入口；内部模块使用同一数据协议，桌面专属能力不出现在移动界面。
