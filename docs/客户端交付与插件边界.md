# 客户端交付与插件边界

文档版本：1.4-draft。按 [ADR 0008](adr/0008-solo-developer-delivery-baseline.md)和 [ADR 0009](adr/0009-electron-desktop-plugin-runtime.md)执行。个人维护，没有官方账号、后台、认证或默认插件仓库。下表区分桌面首版与精简移动目标，未通过实测的平台不列为已支持。

## 1. 首版交付

首版在 Linux 完成 Electron 桌面宿主、插件加载、iframe UI、服务互通、简单 Agent 调用和前台紧急通知，随后适配 Windows。Windows 完成后依次开发 Android、iOS 信息收发器；不规划 macOS。M0 通过 iframe 来源校验、插件信任、Restricted Mode、单写者和回收验证后才开放第三方本地插件入口。

M1 提供已安装列表、本地包导入、权限和来源展示、启停、卸载、手动更新及失败诊断。插件目录、网络下载、CLI 和热重载按后续阶段增加。标准文件/归档查看与结果保存支撑插件使用，不把完整聊天平台或数据管理平台作为前置条件。

随包模块与可选插件通过宿主 API 时按声明和授权访问数据。桌面插件服务采用 VS Code 式信任模型，启用后可使用当前用户的系统权限；安装页必须展示来源、内容摘要、代码执行风险和自述权限。未签名包无需发布者账号或证书，但内容或来源变化后必须重新确认信任。

## 2. 平台目标矩阵

| 能力 | M1 单桌面首版 | 桌面完整包目标 | 移动信息收发器目标 |
|---|---|---|---|
| 本地工作区、文件选择、基础查看、结果保存 | 提供 | 完善搜索、归档和备份 | 消息查看/发送、附件选择和必要设置 |
| 插件管理与互通 | 本地可信插件、已安装依赖、Restricted Mode | 增加开发能力和用户配置的目录源；外部信任信号按可维护条件接入 | 不提供市场、导入或第三方插件；只含随应用编译的内部模块 |
| Agent | `agent-api` profile、持久 runtime 和预授权插件工具 | 扩充 SDK、模型适配器与操作类型 | 不提供 |
| 紧急通知 | 已授权来源的应用前台弹窗 | 系统通知、后台接收按需适配 | 前台弹窗、后台按系统能力降级 |
| 多窗口、批量任务、CLI、热重载 | 后续 | 目标提供 | 不提供 |
| WASM/OS 沙箱运行时、联网连接器 | 后续 | 验证后提供 | 只提供产品内置且经发布验证的连接能力 |

桌面和移动共享数据与服务接口语义，不承诺功能对等。开发顺序固定为 Linux、Windows、Android、iOS，不规划 macOS。实际支持名单注明系统、架构、Electron/Chromium 或移动系统版本及验证日期。缺少硬件、构建工具链或分发资格的平台保持未验证。

## 3. 首版使用流程

本地工作区 → 导入两个兼容离线插件 → 查看权限 → 绑定转换服务 → 选择一份输入 → 返回并保存结果。切换到 Agent 适配器后，可以在预授权范围内调用同一服务、查询和取消任务。测试插件发送本地紧急事件，宿主按来源授权显示前台弹窗。

首次断网可完成上述流程，必要的宿主组件与运行依赖应随包或通过离线安装步骤提供。Agent 测试可以使用本地脚本客户端，不要求模型账号或模型服务；真实 Agent 在应用之外的数据行为不由宿主控制。

归档导出包含消息与附件清单，不包含附件原文件、外部账号或权限。导入和备份规则见[本地数据规范](本地数据与备份恢复.md)。停用转换器不删除已保存结果；插件私有格式需插件自身的导出或交接方案。

## 4. 加载和兼容

桌面 M1 支持 `runtime.ui` 和纯 JavaScript `runtime.extension`；包含 Extension Host 的包必须先明确确认信任。`connectivity: offline` 约束 iframe 和宿主代理，不限制已信任 Node.js 代码直接使用系统网络。manifest 能表达 Worker、联网或其他阶段能力，不意味着客户端支持。未知权限、必需能力缺失、来源冲突或不兼容依赖拒绝激活；可选能力缺失只隐藏相关入口。

本地包执行清单、路径、摘要、资源预算和授权校验。桌面测试目录先复制为受控快照，不能绕开检查。项目不运营默认插件源、签名、扫描或阻止列表；没有用户配置的目录源时只显示本地管理入口，不显示已上线市场、已验证发布者或安全审核状态。

后续联网连接器通过宿主代理访问用户授权目标。服务部署、账号、同步和推送属于接入方，应用不自动提供后台。具体网络能力以实测为准，不能用“中心化/去中心化兼容”替代协议实现。

## 5. 移动精简策略和通知限制

Android、iOS 依次开发为易用、稳定的信息收发器，只提供连接配置、消息列表与详情、发送、附件和通知等必要能力。它们不追求桌面插件级扩展性，不展示插件市场或插件管理，不导入本地插件包，不执行开发目录、下载代码、Extension Host 或第三方二进制。少量内部连接模块作为应用代码或静态资源随包构建，升级只通过应用发布流程完成。新增协议或能力需要重新构建和发布应用，这是缩小攻击面、降低配置复杂度的主动取舍。

移动宿主不定义统一账号。后续开发在构建配置中选择并编译经过验证的内部连接模块：可以是服务器模式、去中心模式，也可以只包含本地能力。服务器模块自行定义服务地址、账号认证、凭据、增量同步、冲突处理和推送通道；去中心模块自行定义本地身份、密钥、发现、连接、同步和消息确认。宿主只提供安全存储引用、标准消息/附件界面、连接状态、任务和平台通知适配，不能把某个模块的账号或拓扑提升为应用全局前提。

构建配置决定安装包包含哪些内部连接模块；用户只能在已编译并验证的模块内配置服务、节点或选择不连接。模块未进入当前安装包时，对应账号、同步、后台接收和跨设备能力均明确不可用，不提供运行时下载入口。

桌面插件不会自动进入移动包。内部模块需由移动客户端显式选择、编译并通过渠道和设备验证；桌面插件授权、信任记录和运行状态不迁移到移动端。桌面仍是服务中立的平台：账号认证、服务器地址、去中心协议和“不使用网络”均由插件及用户选择，宿主不提供统一账号或默认服务。

Android、iOS 前台发送、附件处理等任务可取消，进入后台或被系统终止时记录中断；恢复时重新获取失效句柄。移动端没有第三方插件常驻，后台通知也不依赖未经验证的轮询或免费推送中继。

紧急通知的 M1 承诺仅为：宿主运行且在前台、来源有授权、事件有效时展示弹窗。Android、iOS 后台/锁屏/退出提醒由所选内部连接模块提供到达通道，再由系统通知接口展示；服务器模式可以使用其服务和推送，去中心模式按对应协议及系统后台能力实现。没有连接模块或系统不允许运行时不承诺及时送达。系统接受通知不等于用户看到。详见[通知规范](通知分级与紧急提醒.md)。

## 6. 验收和分发

- 断网完成插件加载、服务绑定、输入授权、结果保存；没有账号或远端源依赖。
- 两插件通过宿主 API 互访私有数据失败，明确授权的资源可传递；停用后旧会话和句柄失效。已信任插件进程的系统访问不在该权限保证内。
- Agent 不点击插件页面即可发现、调用、查询和取消同一服务；越权返回明确错误。
- 授权紧急来源在前台弹窗；未授权、重复、撤回和过期事件正确处理。
- 卡死、超时或迁移失败可关闭插件并恢复数据，不使其他安装失去操作能力。
- 发布说明列明平台验证结果、构建命令、运行依赖、许可证、更新来源与已知限制；手动更新不扩大权限。
- 未信任插件和 Restricted Mode 工作区不会启动第三方服务进程；包摘要或来源变化会撤销原信任并重新确认。
- 移动安装包不存在第三方插件入口、开发加载或桌面 Extension Host。
