# 连接方式与服务中立

应用由个人维护、以开源分发为目标，兼容中心化服务、联邦服务、去中心化网络及纯本地任务。宿主不提供统一账号、默认服务器或固定网络拓扑。服务如何部署、认证、治理和运营由用户选择的插件或内置连接模块及其接入服务决定。

M1 验证离线插件、简单 Agent 与前台通知。本文为后续联网设计，拓扑中立仅表示扩展方向，不表示已有可用连接器。

## 1. 宿主与连接器

| 宿主统一提供 | 连接器决定 |
|---|---|
| 本地工作区、连接配置和受控凭据引用 | 对端协议、登录/配对、节点发现和连接方式 |
| 标准消息、附件、资源引用和来源信息 | 外部对象与标准对象的映射，专有能力 |
| 任务状态、重试/取消接口和错误展示 | 对端发送、确认、同步和一致性语义 |
| 网络能力代理、用户授权和资源限额 | 使用哪些已支持传输；不支持时请求新增能力 |

首批网络能力可以从 HTTP/WebSocket 请求与流开始，具体以运行时实际支持为准。点对点发现、局域网访问、监听端口、WebRTC 或其他传输分别声明能力，经平台适配和用户授权后提供。不能以“去中心化”为理由获得任意 socket 或主机访问。

桌面端只提供平台能力。连接插件可以要求账号，也可以让用户填写自建服务器、选择节点或完全离线；宿主不替插件认证用户，不把某个服务账号转换成全局账号。账号字段、登录流程、令牌刷新、服务端同步和远端删除语义由连接插件契约定义，凭据只能通过宿主安全存储引用或插件明确披露的边界使用。

## 2. 数据和能力

连接器注册自己的身份命名空间；不要求对端账号映射到项目方账号。资源标识包含 `connectionId + remoteId`，不能仅凭显示名、邮箱或正文合并用户与消息。跨连接映射必须有显式关联和来源记录。

统一数据模型保留来源、外部版本和扩展字段引用。标准界面使用共同能力；编辑、撤回、已读回执、线程、离线发送等逐项探测，缺失时明确显示。插件专有字段留在插件数据中，不要求宿主理解全部协议。

本地排队、对端接受、送达和已读是不同状态。连接器报告能证明的确认级别；发生超时但可能已发送时返回结果不确定，宿主和 Agent 不盲目重复发送。离线同步、冲突和重复数据按协议处理，再映射为明确的本地状态。

加密与密钥流程由对应协议适配，不要求把密钥交给其他插件。搜索和 Agent 只能读取本地实际可用且获授权的内容；端到端加密记录在未解密时不能承诺全文搜索。

## 3. 复用

UI 和 Agent 调用相同的查询、发送、导出等服务接口。一个接口可以由不同拓扑的连接器实现；工作区或用户选择提供者，宿主检查接口版本、数据范围和副作用。接口兼容不等于不同服务具备完全相同的同步、隐私或可用性保证。

QQ 等具体平台接入前先确认接口可获得性、登录方式、协议限制和维护成本；没有官方接口或支持时不能将其列为已承诺能力。优先使用公开接口或用户导出的数据，不把账号密码托管、持续协议适配和远端服务运营默认为宿主职责。若协议需要插件持有密钥或不支持宿主凭据代发，需单独设计该凭据边界，不能绕过现有规则。

当前先完善本地宿主与接口，具体连接器按需求逐个实现和验证。项目没有运行某种网络服务的前置义务，也不承诺尚未实现的协议已经可用。

## 4. 移动内部连接模块

Android、iOS 信息收发器不加载桌面插件，并按 Android、iOS 的顺序开发。后续开发通过构建配置选择少量内部连接模块并随应用编译，具体安装包可以采用服务器模式、去中心模式或仅本地模式。新增或替换协议需要重新构建、测试和发布应用；移动端不以运行时扩展性为目标。

- 服务器模式模块负责服务地址、账号认证、凭据生命周期、增量同步、冲突处理、跨设备状态及后台推送。宿主不自动提供这些能力。
- 去中心模式模块负责本地身份、密钥、节点发现、连接建立、消息确认、同步及系统后台受限时的降级。去中心不等于无需身份或无需外部可达条件。
- 仅本地模式不创建账号或连接，只提供安装包内可完成的查看和处理能力，也不宣称具备跨设备同步或后台收信。

移动宿主统一提供安全存储引用、标准消息/附件模型、连接状态、任务、错误展示和系统通知适配。只有模块进入当前构建并通过目标设备验证后，界面才显示其登录、节点、同步和通知设置。用户可以在已编译模块允许的范围内选择服务、节点或不连接；构建外能力保持不可用。
