# InformetionChat 完整架构图

状态：桌面设计基线，2026-09-18。Linux、Windows 桌面架构已冻结但尚待实现验证；Android、iOS 只冻结产品与连接边界，技术栈在对应阶段决定。开发顺序固定为 Linux、Windows、Android、iOS，不规划 macOS。

## 1. 产品与部署全景

```mermaid
flowchart TB
  User[本地用户]

  subgraph Desktop[桌面产品：Linux → Windows]
    Workbench[Electron 工作台]
    Supervisor[Desktop Runtime Supervisor]
    Core[Dart AOT Core Host]
    AgentRuntime[Agent Runtime]
    PluginUI[插件 UI<br/>沙箱 iframe]
    Extension[插件服务<br/>Node utilityProcess]
    LocalData[(SQLite / 附件 / 插件存储)]
    Packages[(只读插件包快照)]

    Workbench --> Supervisor
    PluginUI --> Supervisor
    Extension --> Supervisor
    AgentRuntime --> Supervisor
    Supervisor --> Core
    Core --> LocalData
    Supervisor --> Packages
  end

  subgraph Mobile[移动信息收发器：Android → iOS]
    MobileShell[移动宿主与统一界面]
    BuiltIn[构建时选入的内部连接模块]
    MobileData[(本地缓存 / 安全存储引用)]
    MobileNotify[系统通知适配]

    MobileShell --> BuiltIn
    MobileShell --> MobileData
    BuiltIn --> MobileNotify
  end

  subgraph External[可选外部拓扑]
    Server[用户选择的服务器或自建服务]
    Federation[联邦服务]
    Peer[去中心节点 / 对等网络]
    Offline[纯本地能力]
  end

  User --> Workbench
  User --> MobileShell
  Extension -. 连接插件自行实现 .-> Server
  Extension -.-> Federation
  Extension -.-> Peer
  Core --> Offline
  BuiltIn -. 由构建配置决定 .-> Server
  BuiltIn -.-> Federation
  BuiltIn -.-> Peer
  BuiltIn --> Offline
```

宿主没有统一账号、默认服务器或官方后台。桌面连接插件和移动内部连接模块分别决定是否需要账号、连接哪个服务、使用去中心协议或完全离线。桌面插件不会进入移动安装包，移动内部模块也不是可下载插件。

## 2. 桌面进程与通信

```mermaid
flowchart LR
  subgraph Clients[可信客户端]
    Window[工作台 renderer]
    SDK[本地 API SDK]
  end

  subgraph Electron[每个 profile 唯一 Electron Supervisor]
    Main[Electron Main<br/>进程监管 / 通道路由 / 系统适配]
    ViewA[插件 A iframe<br/>ichat-plugin://origin-A]
    ViewB[插件 B iframe<br/>ichat-plugin://origin-B]
    ExtA[插件 A Extension Host<br/>Node utilityProcess]
    ExtB[插件 B Extension Host<br/>Node utilityProcess]
    Agent[Agent Runtime]
  end

  subgraph CoreProcess[每个 profile 唯一 Dart AOT Core Host]
    Router[身份绑定与 RPC 分发]
    Permission[权限代理]
    Registry[服务注册与提供者绑定]
    Resource[资源句柄]
    Task[任务 / 取消 / 调用栈]
    Notify[通知策略]
    Lifecycle[安装 / 信任 / 生命周期]
    Storage[工作区单写者]

    Router --> Permission
    Permission --> Registry
    Permission --> Resource
    Registry --> Task
    Task --> Notify
    Lifecycle --> Registry
    Router --> Storage
  end

  subgraph Persistent[持久与只读数据]
    DB[(SQLite / WAL)]
    Blob[(附件与结果 blob)]
    PluginStore[(插件私有存储)]
    Snapshot[(校验后的包快照)]
    Profile[(profile 锁 / 授权 / 绑定)]
  end

  Window -->|限定 Electron IPC| Main
  SDK -->|Linux UDS / Windows Named Pipe| Main
  ViewA -->|精确 origin + frame + MessagePort| Main
  ViewB -->|精确 origin + frame + MessagePort| Main
  ExtA -->|专用 MessagePort| Main
  ExtB -->|专用 MessagePort| Main
  Agent -->|私有管道| Main
  Main -->|4 字节长度 + JSON-RPC / stdio| Router

  Storage --> DB
  Resource --> Blob
  Storage --> PluginStore
  Lifecycle --> Snapshot
  Storage --> Profile
```

Supervisor 只监管进程、绑定通道身份和适配操作系统，不复制权限或业务规则。Core Host 是工作区唯一写入宿主；第二窗口和 Agent client 连接已有 Supervisor，不能创建第二个 Core 直接打开数据库。

## 3. 插件安全边界

```mermaid
flowchart TB
  Package[本地插件包]
  Stage[暂存、路径检查、摘要、只读快照]
  Consent{用户确认运行等级与来源}
  Restricted{工作区是否 trusted}

  subgraph WebTier[Web 沙箱 UI]
    Origin[按工作区 + 安装 + 摘要派生 origin]
    CSP[CSP + session 请求拦截]
    Bridge[窄 MessageChannel Bridge]
  end

  subgraph TrustedTier[受信任 Node.js 本地代码]
    ExtensionHost[每安装 Extension Host]
    SystemAccess[当前用户的文件 / 网络 / 进程权限]
  end

  subgraph FutureTier[后续受限计算]
    Wasm[WASM / OS 沙箱]
  end

  Package --> Stage --> Consent --> Restricted
  Restricted -->|trusted + runtime.ui| Origin --> CSP --> Bridge
  Restricted -->|trusted + runtime.extension| ExtensionHost --> SystemAccess
  Restricted -. 后续 .-> Wasm
```

Web UI 不能访问 Node.js、Electron、任意本地路径或网络。Node.js Extension Host 采用 VS Code 式信任模型，拥有当前用户的系统权限；宿主 API 权限不能限制恶意 Node.js 代码。需要强隔离的代码只能进入后续 WASM 或 OS 沙箱运行时。

## 4. 跨插件服务调用

```mermaid
sequenceDiagram
  actor User as 用户
  participant AUI as 插件 A iframe
  participant S as Electron Supervisor
  participant Core as Dart Core Host
  participant B as 插件 B Extension Host
  participant Data as 资源存储

  User->>AUI: 选择输入并触发操作
  AUI->>S: host.file.pick
  S->>Core: 绑定 A 身份后转发
  Core->>Data: 创建 A 可读的短期句柄
  Core-->>AUI: opaque resource handle
  AUI->>S: host.service.call(service, handle)
  S->>Core: 转发已绑定会话
  Core->>Core: 检查授权、绑定、版本、schema、调用环
  Core->>Data: 派生仅 B、本次调用可读的句柄
  Core->>B: plugin.service.invoke
  B->>Core: 读取派生资源
  Core->>Data: 校验接收者和有效期
  Data-->>B: 分块内容
  B-->>Core: 符合 outputSchema 的结果
  Core->>Data: 生成归属 A 的结果句柄
  Core-->>AUI: task succeeded + result handle
  Core->>Data: 撤销 B 的临时输入句柄
  User->>AUI: 保存结果
  AUI->>Core: host.file.save(result handle)
```

插件之间没有直接通道。服务注册、提供者选择、参数校验、任务、取消和资源派生全部经过 Core Host。Agent 调用同一服务管线，只增加 Agent 会话、工具暴露和效果授权的交集检查。

## 5. 生命周期与资源策略

```mermaid
stateDiagram-v2
  [*] --> Discovered
  Discovered --> Validated: 清单 / 路径 / 摘要通过
  Validated --> Disabled: 保存安装记录
  Disabled --> Active: 插件与工作区均可信 + 激活事件
  Active --> IdleCandidate: 无视图 / 任务 / RPC / 后台活动
  IdleCandidate --> Active: 新的命令、视图或服务调用
  IdleCandidate --> Suspended: 连续闲置 5 分钟
  Suspended --> Active: 冷启动 Extension Host 与 iframe
  Active --> Disabled: 用户停用
  Suspended --> Disabled: 用户停用
  Disabled --> [*]: 卸载；数据另行确认
  Active --> Failed: 崩溃 / 超时 / 契约错误
  Failed --> Disabled: 诊断后停止
```

桌面进程组每秒统计 RSS。达到 4 GiB 时停止后台预热，达到 4.5 GiB 时拒绝新的后台激活并优先回收已闲置 5 分钟的运行时。超过 5 GiB 时展示进程、安装、任务和增长明细，建议用户审查；宿主不自动终止正在使用的插件。

## 6. 移动连接边界

```mermaid
flowchart LR
  Build[移动构建配置]
  ServerModule[服务器模式内部模块]
  PeerModule[去中心模式内部模块]
  LocalModule[仅本地内部模块]
  Shell[Android / iOS 移动宿主]

  Build -->|选入并随包编译| ServerModule
  Build -->|选入并随包编译| PeerModule
  Build -->|选入并随包编译| LocalModule
  ServerModule --> Shell
  PeerModule --> Shell
  LocalModule --> Shell

  ServerModule --> ServerDuty[账号 / 凭据 / 同步 / 冲突 / 推送]
  PeerModule --> PeerDuty[身份 / 密钥 / 发现 / 同步 / 后台降级]
  LocalModule --> LocalDuty[本地查看与处理]
  Shell --> Common[消息与附件 UI / 安全存储引用 / 任务 / 系统通知]
```

移动端的低扩展性是主动取舍。新增协议或能力需要重新构建、测试和发布应用，以换取更少的配置、更小的攻击面和更稳定的使用体验。服务器模式才引入对应的账号、服务端同步和推送设计；去中心模式按自身协议处理身份、密钥和同步；仅本地模式不承诺跨设备或后台收信。
